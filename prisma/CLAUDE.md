# prisma — schema, migrations e seed (PostgreSQL + pgvector)

Fonte de verdade do modelo de dados. Mudança aqui é irreversível em dados e afeta o client gerado, então revise o SQL antes de aplicar.

## Responsibility

Pertence aqui: `schema.prisma`, `migrations/<timestamp>_<nome>/migration.sql`, `seed.ts` e `seed-data/`. NÃO pertence: o singleton do client (`src/lib/db.ts`, export `db`), queries e regras de negócio (`src/domains/*/services/`) e validação de entrada (`src/lib/validators/`).

## Key patterns

- `MaterialChunk` tem colunas `Unsupported("vector(1024)")` (`embedding`) e `Unsupported("tsvector")` (`contentTsv`), criadas em `20261020130000_pgvector_fulltext` com índices HNSW/GIN. O Prisma não as modela.
- `prisma migrate dev` gera `DROP` espúrios dessas colunas/índices por drift. Revise o `migration.sql` gerado e remova qualquer DROP de `embedding`, `content_tsv` e dos índices antes de aplicar. Fluxo: skill `/create-migration`.
- Tabelas com `@@map` snake_case (`courses`, `users`); ids `cuid()`; `updatedAt @updatedAt`.
- Enum novo via migration `ALTER TYPE ... ADD VALUE IF NOT EXISTS` (ex.: `20261108200000_group_message_event`).
- `seed.ts` chama `assertSeedAllowed` (`seed-data/production-guard.ts`): bloqueia em produção sem `ALLOW_SEED_IN_PRODUCTION`. Cria contas demo com senhas públicas.
- Após `prisma generate`, reinicie o `next dev`: o client em memória (`globalForPrisma`) fica obsoleto.

## Applied rules

Rules active in this directory — read them before touching code here:

- @.claude/rules/06-security.md — nunca versionar segredos/URLs com credencial; queries parametrizadas (use `$queryRaw` com template, nunca concatenação); não gravar dado sensível sem necessidade.
- @.claude/rules/05-testing.md — seed e guardas (`production-guard`) têm teste; não testar schema/código gerado.

## Local conventions

- NUNCA rodar `db:seed`/`prisma migrate reset` no banco de dev da porta 5432; use banco/porta isolado de teste.
- Migration em pt-BR no comentário SQL, nome `AAAAMMDDHHMMSS_assunto`, uma mudança lógica por migration.
- Backfill de dados em migration separada (ex.: `aulas_capitulos_backfill`).
- `prisma:migrate` = `prisma migrate dev`; produção usa `migrate deploy`.
